# mossy-frontmatter

Optimize skill frontmatter descriptions to improve Vibe auto-activation. This skill systematically analyzes existing skill frontmatter and modifies the description field to ensure skills are activated when user prompts demand functionality that the skill can provide.

Vibe auto-triggers skills based on description matching (confirmed via upstream changelog:2573). This skill provides data-driven optimization of the description field to maximize relevant activations while avoiding false positives.

## Parameter

This skill accepts as a parameter the name of a single skill (e.g. `mossy-scan`) or a wildcard pattern (e.g. `*-interview`).
It then optimzes the frontmatter of all matching skills.
An optional switch `-v` or `--verbose` activates verbose mode
An optional switch `-vv` or `--veryverbose` activates very verbose mode

## Procedure to optimize one skill

- Prepare TRIGGERS.md in the skill directory (see section TRIGGERS)
- Read the skill frontmatter, note the old description
- Determine the old description's `SCORE` (see section SCORE)
- Loop:
  - Use an exploratory subagent to come up with an ten alternative description for the skill, using high temperature setting for the LLM to give good variation. The subagent may read the entire `SKILL.md`.
  - For each alternative description:
      - Determine the alternative description's `SCORE`
      - If the new score is higher, replace the skill description in `SKILL.md` with the new one and remember the new `SCORE` as reference
  - If no better replacement was found, declare the work finished; print the `SCORE` we started with, and the final `SCORE`, and exit the loop
  - Repeat the loop

## TRIGGERS

- Each skill to optimize shall contain a file `TRIGGERS.md` with a positive list of trigger phrases in section `Should Trigger` and a negative list of trigger phrases in section `Should Not Trigger`
- A sample `TRIGGERS.md` is available in the mossy-frontmatter folder itself, with phrases matching this skill
- At start, verify that `TRIGGERS.md` exists and contains at least 30 appropriate positive trigger phrases and 30 negative trigger phrases
- Positive trigger phrases to fill up the file should be generated by an exploratory subagent. Prompt: `Read the entire skill <skill name> and come up with user prompts where activating the skill would be helpful.`
- Analogously, negative trigger phrases can be generated by the prompt `Read the entire skill <skill name> and come up with user prompts where activating the skill would NOT be helpful.`

## SCORE

To determine a description's SCORE, follow this procedure:
- Let `N_P` be the number of positive trigger phrases in `TRIGGERS.md`
- Let `N_N` be the number of negative trigger phrases in `TRIGGERS.md`
- Let `N_TP` be the number of posive trigger phrases in `TRIGGERS.md` that would activate `<skill name>` with description `<description>` (true positives)
- Let `N_FN` be the number of negative trigger phrases in `TRIGGERS.md` that would activate `<skill name>` with description `<description>` (false negatives)
- With the usual definitions `Sensitivity = N_TP/N_P` and `Specificity = 1 - N_FN/N_N`, the `SCORE` is `Sensitivity * Max(0, Specificity - .75)`. Rationale: This product heavily punishes false negatives.

If very verbose mode is on, print the result from each test. If very verbose or verbose mode is on, print `<description>`, `Sensitivity`, `Specificity` and the final `SCORE`.

Note: To test how many trigger phrases would activate `<skill name>` with description `<description>`, 
  feed the output of `generate-skill-oracle-prompt.sh <skill name> <positive/negative> "<description>"` to a subagent. In the output, count the occurences lines containing only `<skill name>`. <positive/negative> is to be the flag `-p` for positive triggers and `-n` for negative triggers.
